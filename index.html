Built for Absolute Correctness

No complex CRDT bloat. Just rock-solid monotonic sequence synchronization with zero third-party dependencies.

⚡

Instant Optimistic UI

Local updates reflect on screen in 0 milliseconds. All ops carry a unique client-generated opId so retries are guaranteed idempotent with no duplicate executions.

🎯

Authoritative Monotonic Seq

State keys resolve via strict Last-Write-Wins (LWW) ordered by the server-assigned sequence number, completely eliminating race conditions caused by client clock skew.

🛡️

Crash-Resilient Catch-Up

Offline keystrokes are queued in memory and sessionStorage. On reconnect, the client resumes with exponential backoff and automatically replays missed sequence ops.

🖱️

Ephemeral Presence & Cursors

Throttled (~30ms) live cursor broadcasts with auto-rendering, smooth CSS interpolation, and avatar presence bars that never flicker during brief reconnects.

💾

Persistent Rooms

Debounced atomic storage commits ensure rooms survive full server restarts. Unused idle rooms are automatically recycled via configurable TTL policies.

🎛️

Token-Bucket Rate Limiter

Strict per-connection and per-IP token bucket limits protect the server from spam bursts, returning explicit rate_limited frames with retry backoffs.

How Synchronization Works

A clean three-stage flow: Optimistic Local Mutation → Authoritative Sequencing → Deterministic Reconciliation

STEP 1

Client Generates Op

room.set(key, val) generates a unique opId, applies local state immediately, updates the UI, and queues the op for transmission.

STEP 2

Server Sequences Op

The authoritative Node.js server validates payload schemas, increments the monotonic sequence seq += 1, checks opId idempotency, and broadcasts the frame.

STEP 3

Peers Converge

Receiving peers apply the authoritative op. If the sender was offline, their local queue is drained and reconciled against the server log.
